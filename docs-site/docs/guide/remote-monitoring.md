# 远程主机监控

NyaTerm 为 SSH 会话提供了五类右侧监控面板：**资源监控**、**NVIDIA GPU 监控**、**Ascend NPU 监控**、**进程管理**、**Docker 管理**。它们有一些共同点：

- 只在当前是 **SSH 会话** 时才有意义，并且只绑定到真正处于活动状态的 SSH 会话
- 各自由 **设置 → 终端** 中的开关控制是否显示；关闭对应开关会同时隐藏它的活动栏图标
- GPU、NPU、进程和 Docker 面板的轮询间隔范围为 **3 秒到 120 秒**；资源监控面板单独支持 **1 秒到 60 秒**
- 面板会在连续轮询失败若干次后停止刷新，避免对不支持的主机反复请求

默认开关状态如下。注意进程管理和 Docker 管理是**默认开启**的：

| 面板 | 设置项 | 默认 | 默认间隔 |
|------|--------|------|----------|
| 资源监控 | 显示远程资源信息 | 开启 | 3 秒 |
| NVIDIA GPU 监控 | 显示 NVIDIA GPU 监控 | 关闭 | 3 秒 |
| Ascend NPU 监控 | 显示 Ascend NPU 监控 | 关闭 | 3 秒 |
| 进程管理 | 显示进程管理 | 开启 | 5 秒 |
| Docker 管理 | 显示 Docker 管理 | 开启 | 10 秒 |

## 资源监控

远程资源监控默认开启。要看到数据，需要同时满足：

1. 当前是一个 **SSH 会话**
2. 在 **设置 → 终端** 中开启 **显示远程资源信息**

启用后，右侧 **资源监控** 图标会显示，面板会按设定间隔轮询主机信息；默认轮询间隔为 **3 秒**，可手动调整。

面板会显示的内容包括：

- 主机名、系统、架构、运行时长
- Load Average
- CPU 使用率
- 内存使用情况
- 网络吞吐速率

## NVIDIA GPU 监控

**NVIDIA GPU 监控** 面板用于查看远端主机上的 NVIDIA GPU 状态，默认关闭，可在 **设置 → 终端** 中开启 **显示 NVIDIA GPU 监控**。

面板会显示：

- 驱动版本与 CUDA 版本
- 汇总信息：GPU 数量、最高使用率、显存占用、最高温度
- 每张 GPU 卡：编号、型号、性能状态（pstate）、使用率与显存占用条，展开后可看 UUID、温度、功耗、风扇转速、空闲显存；使用率超过 **70% / 90%** 时会有不同的颜色提示
- 可搜索的 GPU 进程列表（按 PID、GPU 编号、用户或进程名过滤），按显存占用排序

如果远端没有 NVIDIA GPU 或缺少 `nvidia-smi`，面板会给出对应的空状态提示。

## Ascend NPU 监控

**Ascend NPU 监控** 面板用于查看远端主机上的昇腾 NPU 状态，默认关闭，可在 **设置 → 终端** 中开启 **显示 Ascend NPU 监控**。

面板会显示：

- 驱动版本与 CANN 版本
- 汇总信息：NPU 数量、最高 AI Core 使用率、内存占用、最高温度
- 每个设备：设备号、Physical ID、Bus ID、AI Core 使用率、内存占用、温度与功耗
- 可搜索的 NPU 计算进程列表

如果远端主机不返回 Ascend NPU 信息，面板会给出对应的空状态提示。

## 进程管理

**进程管理** 面板显示远端主机的实时进程列表，**默认开启**，可在 **设置 → 终端** 中通过 **显示进程管理** 关闭。

主要能力：

- 进程总数与搜索框（可按 PID、用户、状态、命令、完整命令行过滤）
- 自适应布局，根据面板宽度增减列；可按进程名、PID、CPU%、内存%、用户排序
- 展开某个进程可查看 PID/PPID、用户、状态、CPU%、内存%、RSS、运行时长与完整命令行，并支持调整 nice 值（`-20` 到 `19`）后 **应用**（renice）
- 行操作菜单可复制 PID / 命令，或发送 `TERM` / `HUP` / `STOP` / `CONT` 信号；`KILL` 会先弹出确认对话框并展示对应的 `kill` 命令

若远端主机不支持进程查询，面板会给出单独的提示。

## Docker 管理

**Docker 管理** 面板用于管理远端主机上的 Docker，**默认开启**，可在 **设置 → 终端** 中通过 **显示 Docker 管理** 关闭。

主要能力：

- 概览：运行中 / 已停止容器数、镜像数，标题栏显示 Docker 引擎版本
- 全局搜索，以及容器、镜像、数据卷、网络、Compose（可用时）等标签页，标签过多时收进 **更多** 下拉
- **容器**：按状态排序的虚拟化列表，行菜单可查看日志（在终端里运行 `docker logs -f`）、进入容器（打开 shell）、启动 / 停止 / 重启 / 杀死（确认）/ 删除（确认）；点击行可打开实时刷新的详情对话框
- **镜像 / 数据卷 / 网络**：按需加载，每行支持删除（确认）
- **Compose**：列出项目，展开后按需加载服务，支持项目级 up / restart / down 与服务级 logs / enter / up / stop / restart
- **更多** 菜单提供 `docker system prune`（危险操作，需确认）

日志与进入容器会发送到真实的终端会话中执行；删除、杀死、Compose down、prune 等破坏性操作都会通过确认对话框展示将要执行的具体命令。

# 文件传输性能修复与验证（2026-10-23）

## 范围与原因

本次修复针对 GPUI 版本相对 `temp/nyaterm-tauri` 的代码差异。原下载默认只有约
32 KiB × 3 个在途请求，目录内进一步收缩到每文件一个读取；上传未显式设置新版本
SFTP 库的写包参数，实际可能退回约 32 KiB；下载提交还会完整复制一次暂存文件并强制
同步。SSH 接收窗口与 TCP_NODELAY 也与 Tauri 不同。这些差异足以影响吞吐，不能只归因于
用户配置。实际收益仍取决于 RTT、服务器限额、磁盘、杀毒软件和构建类型。

存储字段、用户保存的线程数、凭据、备份和固定依赖版本均保持兼容；没有修改 `temp/`。

## 最终行为

- 每个窗口共享外层队列，下载和上传各自使用 `max(1, clamp(线程数, 1, 10) - 1)`
  个名额，复制队列使用两个值的较小值。暂停释放名额，恢复进入队尾，减少设置值不抢占
  已运行任务。未启动就取消的任务不会执行网络操作。交互式浏览、预览、编辑器仍使用原调度。
- 请求配置限制为 64–256 KiB，每包预留 1 KiB。读取自动深度为
  `ceil(1024 KiB / 配置请求大小)`，限制 4–16；手动深度限制 4–64，兼容模式为 1。
  已知长度文件共享一个句柄并发 `read_at`，按偏移提交，补齐短读。
- 目录默认两个传输会话、最多 16 个文件 worker、最多两个大于 512 KiB 的文件同时传输。
  扫描会话在传输前释放。服务器句柄预算可降低 worker，32 MiB 预算可进一步降低每文件
  读取深度（包括手动设置）。该预算计算组装结果和在途回复，不含目录清单及 SSH 协议层内存。
- 上传显式设置写包上限，自动 ACK 深度维持 2 MiB 目标与 8–16 范围；手动设置 4–64，
  兼容模式为 1。普通上传通过 `shutdown()` 等待 ACK 和关闭，不额外发远端 fsync。
- SSH 接收窗口 32 MiB，最大包 32 KiB，直连启用 TCP_NODELAY。
- SFTP/SCP 下载在目标同目录创建暂存文件，等待异步写结束后关闭、直接提交；保留时间戳时
  在关闭前设置。新文件禁止覆盖，授权覆盖替换文件身份。普通下载不 `sync_all()`。
  编辑器和本地复制继续使用原提交实现。Unix 新文件遵循 0666/umask，覆盖只继承普通权限位；
  Windows 按目标目录继承 ACL。续传准备复制已有前缀，失败/取消仅在启用续传且目标校验
  通过后发布连续前缀，并更新任务所有权身份。

## 自动化验证

模拟 SFTP peer 使用请求计数与同步屏障控制回复，不用吞吐阈值断言。覆盖普通/目录读取
16 深度、手动 4/64、兼容模式 1、写包实际长度与 ACK 窗口、服务器限制、短读、未知长度、
目录 worker 与句柄限制、混合大小文件、空子目录、非 UTF-8 远端路径、连续续传前缀和重试身份。
已有测试继续覆盖首次失败后停止接纳并回收已接纳目录任务、编辑器提交与 SCP 流式失败/取消。

队列测试覆盖跨会话方向配额、FIFO、暂停释放、恢复、动态增减、复制额度、重试、排队取消、
会话关闭和窗口关闭。Windows 测试覆盖直接提交的文件身份、覆盖、目标竞争、文件占用、
暂存清理、ACL 与时间戳。Unix 权限测试已加入，但本次 Windows 环境无法执行。

## 真实环境性能验收：尚未执行

本环境没有 `NYATERM_TEST_SFTP_*` 测试服务器配置，也没有可复现的 Tauri 实测数据。
不能据模拟测试宣称达到 Tauri 的 1.1 倍总耗时目标，也没有编造修复前后速度。

准备相同服务器上的三个只读测试源：1 GiB 文件、5000 个小文件、混合目录。三个版本均使用
release 构建、同一账号/SSH 参数、相同网络和目标磁盘；每次使用新目标目录。建议交错运行
修复前、修复后与 Tauri，各五次，取中位数；保持防病毒、磁盘缓存和服务器负载条件一致。
分别测下载、上传；自动 harness 只覆盖当前引擎下载，外层队列和 Tauri 对照需要应用实测。

已有 E2E 的主机、端口、用户名、密码环境变量继续有效。额外设置：

- `NYATERM_BENCH_LOCAL_ROOT`：目标磁盘上已有的测试根目录。
- `NYATERM_BENCH_FILE`：服务器上恰好 1 GiB 的普通文件。
- `NYATERM_BENCH_SMALL_DIR`：含 5000 个文件的服务器目录。
- `NYATERM_BENCH_MIXED_DIR`：含大小文件及子目录的服务器目录。

运行：

```powershell
cargo test --release -p nyaterm-transport --test sftp_service_e2e sftp_download_release_benchmark_five_samples -- --ignored --exact --nocapture
```

harness 不修改远端；每次在指定磁盘创建并清理新目录，验证与清理不计入传输总耗时。
输出仅包含字节数、文件数和时间，不输出源路径或凭据。

应用开启 `nyaterm_transport::sftp=debug` 日志过滤时，`SFTP file download timings` 包含
`request_bytes`、`reads`、`transfer_us`、`commit_us`、`total_us`；
`SFTP directory download timings` 额外包含 `workers` 与 `scan_us`，均不包含用户路径或内容。
文件传输时间包括写入与 ACK 等待；目录 `transfer_us` 是扫描结束后的墙钟时间，包含建连、
传输、并发提交和清理。目录各文件的 `commit_us` 可求和作为累计提交开销，提交与其他文件
传输存在重叠，不能把它直接加到目录墙钟时间上。GUI 总耗时还应从排队前至完成计时，
与引擎内部时间分别记录。性能采样输出只保留时间、字节/文件数和有效并发参数。

最终记录每个场景的扫描、传输、累计提交、端到端总耗时中位数，计算
`修复后总耗时 / Tauri 总耗时 <= 1.1`；未达到时按阶段定位，不能以模拟并发结果代替验收。
